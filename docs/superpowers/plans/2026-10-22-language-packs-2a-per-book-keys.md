# Language packs 2a: per-book keys Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Derived cache keys (quote, alignment) name the content of the book they were computed from, not the
resource's release, so a release that leaves a book unchanged keeps that book's keys — in the pack build, in Servos and
in tc-study's app.

**Architecture:** A download records each book file's git blob sha (from Door43's tree, one request per repository)
in the resource's catalog row, `contentMetadata.bookBlobs`. One function, `bookContentStamp(metadata, book)`, turns
that into the stamp every derived key uses (`g` + ten hex characters), and falls back to the release stamp when the
row has no blob for the book. Every place that stamps a quote or alignment key takes the book. The warm maps become
per-book resolvers; garbage collection and the pack's original-release check compare per book. The quote and
alignment versions go up, so the compat key changes.

**Tech Stack:** TypeScript; Bun tests in tc-study packages (`bun test`); tc-study's app tests with its own runner
(`apps/tc-study`, `bun run test` / vitest as the package says).

**Spec:** `docs/superpowers/specs/2026-10-21-language-packs-parts-design.md` (translation-helps-mcp), §3 «Derived
keys lose the release» and §6 delivery 2a.

(`feat/packs-per-book-keys`). Task 7 also touches translation-helps-mcp (`CURRENT_PACK_COMPAT`).

## Global Constraints

- A book's stamp is `g` + the first ten hex characters of its file's git blob sha, taken from Door43's tree at the
  release tag. Hex never holds `@`, `:` or `+`, which the key parsers split on.
- No blob for a book (an old catalog row, Door43 unreachable, OBS, articles) → the release stamp, exactly as today.
- Book codes are compared lowercase (keys write `book.toLowerCase()`).
- helps-text (TA/TW titles and previews) keeps its resource-level stamp: titles come from one `toc.json` per
  resource, not from a book.
- Nothing is published: no deploy, no bucket write.
- Code comments and commits in English; commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- A resource whose catalog row is regenerated by `createResourceMetadata` (≤ 10 ingredients) after a download: the
  regeneration must keep `bookBlobs`. Pinned in Task 2.
- A new release of a resource whose book did not change: its book stamp stays, its derived rows survive warm GC.
  Pinned in Task 5.
- A new release that changed the book: the stamp changes and the old rows are collected. Pinned in Task 5.
- A pack imported on a device whose original (UGNT/UHB) has the same book blob but another release: its quote and
  alignment rows are kept (today the whole layer is dropped). Pinned in Task 6.
- An old device cache with release-stamped keys: GC removes them once (their stamps no longer match). Pinned in
  Task 5.
